# Dz2link

سحب يومي شفاف وقابل للتحقق: الزائر يضغط **شارك**، يمر على روابط الاختصار، ثم يضع **Binance ID** في صفحة التحقق. بعد انتهاء المؤقت يُختار 100 فائز بصيغة معلنة يستطيع أي شخص إعادة حسابها.

الواجهة ملفات ثابتة تُستضاف على **GitHub Pages**، والمنطق والبيانات على **Supabase** (PostgreSQL) عبر دوال SQL آمنة. لا يوجد خادم تديره ولا مكتبات تحتاج بناءً.

## البنية

```
site/                       ← ما يُنشر على GitHub Pages
  index.html                الرئيسية: المؤقت، الجوائز، البطاقات، زر «شارك»
  verify.html               صفحة التحقق: إدخال Binance ID برمز المهمة
  winners.html              الفائزون + «تحقق بنفسك»
  admin.html                لوحة الإدارة: نشر القائمة، السحب، تعليم الدفع، CSV
  assets/css/main.css       التصميم (أزرق + برتقالي)
  assets/js/config.js       ⚙️ الإعدادات (عدّلها هنا)
  assets/js/api.js          الاتصال بـ Supabase + وضع تجريبي
  assets/js/draw.js         خوارزمية السحب (مشتركة مع الاختبارات)
supabase/schema.sql         الجداول والدوال والصلاحيات
tests/                      اختبارات الخوارزمية والوضع التجريبي
tools/verify-draw.mjs       تحقق مستقل من أي سحب
.github/workflows/pages.yml اختبار ثم نشر تلقائي عند كل push
```

## كيف يعمل

1. **شارك:** `start_session()` تنشئ رمزاً فريداً للزائر، ويُحوَّل إلى رابط الاختصار الذي وجهته `verify.html?t=الرمز`.
2. **صفحة التحقق:** `check_session()` تفحص الرمز، و`submit_entry()` تقبل الـ ID فقط إذا كان الرمز صالحاً ولم يُستخدم ومرّ عليه الحد الأدنى من الوقت (افتراضياً 20 ثانية).
3. **منع التكرار:** قيد فريد على (الجولة، الـ ID) في قاعدة البيانات، وحد لعدد المشاركات من الاتصال الواحد.
4. **الجولات:** كل 24 ساعة جولة: 14 ساعة تسجيل ثم 10 ساعات إغلاق. الوقت من الخادم ولا يمكن التلاعب به من المتصفح.
5. **السحب:** من لوحة الإدارة تنشر القائمة (فتظهر بصمتها SHA-256)، ثم تسحب ببذرة عامة تعلنها.

## التشغيل التجريبي (بدون أي إعداد)

```bash
npm run serve        # ثم افتح http://localhost:8080
npm test             # يتطلب Node 20+
```

بدون بيانات Supabase تعمل الصفحات بوضع تجريبي (يظهر شريط برتقالي في الأعلى). يلزم خادم محلي، فملفات ES modules لا تعمل بفتح الملف مباشرة.

## الإعداد الكامل

**1) قاعدة البيانات**
1. أنشئ مشروعاً مجانياً في [supabase.com](https://supabase.com).
2. افتح **SQL Editor** والصق محتوى `supabase/schema.sql` ونفّذه.
3. من **Project Settings → API** انسخ `Project URL` و`anon public key`.

**2) الإعدادات**
عدّل `site/assets/js/config.js`: ضع `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SHORTENER_TEMPLATE`.
مثال للقالب في معظم مواقع الاختصار: `https://YOUR-SHORTENER/st?api=YOUR_KEY&url={url}`.

**3) حساب الإدارة**
1. في Supabase: **Authentication → Users → Add user** (بريد وكلمة مرور قوية).
2. نفّذ في SQL Editor:
```sql
insert into admins (user_id) select id from auth.users where email = 'you@example.com';
```
3. ادخل من `/admin.html`.

**4) النشر على GitHub Pages**
1. ارفع المشروع إلى مستودع GitHub على الفرع `main`.
2. **Settings → Pages → Source: GitHub Actions**.
3. أي push جديد يشغّل الاختبارات ثم ينشر مجلد `site/` تلقائياً.

## الروتين اليومي

1. بعد إغلاق التسجيل: **الإدارة ← نشر القائمة والبصمة**، وأعلن البصمة على البث.
2. أعلن مسبقاً مصدر البذرة، مثلاً: «hash أول بلوك بيتكوين بعد الساعة كذا».
3. على البث المباشر: الصق البذرة واضغط **إجراء السحب**.
4. حوّل الجوائز عبر Binance Pay (زر **تصدير CSV** أو **نسخ الـ IDs**) ثم علّمها **مدفوعة**.

لتغيير الجوائز نفّذ مثلاً:
```sql
update settings set prizes = '[{"from":1,"to":1,"each":10},{"from":2,"to":100,"each":1}]'::jsonb where id = 1;
```
وبنفس الطريقة يمكن تعديل `open_hours` و`gap_hours` و`min_seconds` و`max_per_ip`.

## التحقق المستقل من السحب

`winners.html` تعيد الحساب في متصفح الزائر. ومن الطرفية:

```bash
node tools/verify-draw.mjs entries.json "البذرة" 100 "البصمة_المنشورة"
```

الصيغة: `k = int(SHA256(seed + ":" + i)[0:12]) mod len(remaining)`، والفائز i هو `remaining[k]` ثم يُحذف من المتبقين.

## حدود الحماية (اقرأها)

- **لا يمكن إثبات أن الزائر شاهد الإعلانات فعلاً** بصفحة ثابتة. الرمز والوقت الأدنى يرفعان تكلفة التحايل لكنهما لا يلغيانه. الأقوى أن تسأل شركة الاختصار هل توفر إشعاراً تلقائياً (postback) عند اكتمال المهمة، ثم تربطه بدالة Edge Function.
- **مفتاح API الخاص بشركة الاختصار** يظهر في `config.js` لأنه في الواجهة. إن كان المفتاح يسمح بسحب الأرباح أو تغيير الإعدادات فلا تستخدمه هنا، بل استخدم مفتاح إنشاء الروابط فقط أو انقل إنشاء الروابط إلى Edge Function.
- الاتصالات المشتركة (شبكات الجوال) قد تشترك في IP واحد، فأبقِ `max_per_ip` معقولاً.
- أنت مسؤول عن مطابقة السحب لقوانين بلدك ولشروط شركة الاختصار.

## ما تم اختباره

اختبارات `npm test` تغطي خوارزمية السحب (وقد طُوبقت مع تنفيذ مستقل بـ Python) ومسار المشاركة في الوضع التجريبي، وجُرّبت الصفحات في متصفح حقيقي. أما `schema.sql` فلم يُنفَّذ على Postgres حقيقي أثناء الإنشاء، فجرّبه على مشروع Supabase جديد قبل الإطلاق، وراقب أي رسالة خطأ عند التنفيذ.
